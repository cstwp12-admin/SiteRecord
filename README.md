# SiteRecord — Field observation pilot

Open https://cstwp12-admin.github.io/SiteRecord/ in Android Chrome.

Offline field notes, photographs and PDF/Word observation reports for inspectors, engineers and site personnel. This repository hosts application build files, not notebook records.

## Phase 5.2 — Verification outcomes and outstanding register

On an original finding, choose the event and **Record verification**. Record outcome, verifier, date and written basis, then mark the check Reviewed only after review. Reviewed verification records are retained; corrections/reopening use a new check. A response alone never resolves a finding. Changed, conflicting or known missing context requires recheck; restore known missing references before verifying again.

Open **History → Outstanding findings** for the attention register. Prepare a report for the current view to retain dated status, verifier references and full verification notes in PDF/Word. Review all notes before sharing. Status is based on records present in this notebook, not authenticated approval or contractual close-out.

**Compatibility:** save/close editors and download a backup before updating. Refresh every tab and update both devices; do not downgrade an upgraded notebook. The atomic record-store migration protects new reports from older readers/writers. New verification/register packages use version 3; this app reads 1/2/3. Android physical acceptance and Phase 5.3 memo assembly remain pending.

## Phase 5.1 — Linked follow-up and response records

Open a saved finding and use **Follow-up & responses**. Choose an existing event (create a revisit event first if needed) and category, then **Start linked record**. Record later facts, photos, an optional party and target date. The new record starts empty and retains a fixed reference to its source. Backlinks open the exact source/child. PDF and Word reports include the reference when the linked record is selected. No delivery, compliance or closure is implied.

**Compatibility:** Save/close editors and download a backup before updating. Update every open tab and both devices. This release atomically upgrades the local record store and guards it against earlier application writers. Do not downgrade afterward. Linked-content backups/event packages use version 2; this release reads versions 1 and 2. Source events are not automatically disclosed in a linked event package; the import preview warns about absent editable source findings. Verification outcomes and memo assembly remain later checkpoints.

## Phase 4.3 — Observation history and comparison

Open **History** to retrieve saved findings across events in your current project. Filter by structure, text or an explicit location role and chainage range. Select two findings and choose **Compare selected** for their complete context, facts, assessment, discussion, references and captioned photographs. Desktop shows two columns; phone stacks the records. **Open in notebook** returns to the exact source finding.

This is current saved-record history, not previous-edit history or verified before/after linkage. A/B follow selection order. Compliance and closure require review. Underlying records remain unchanged; use Reports for PDF/Word output. History works offline with the records present on this device.

## Phase 4.2 — Faster repeat work

Reports now offer named saved report settings, named saved filters and a remembered report type. Event and observation editors offer explicitly selected recent locations, separated by venue, affected location and sample origin. Filters leave report selection unchanged; review the hidden-selection warning. Report settings never save finding selections or issued report references.

Saved shortcuts belong to this browser/project and are excluded from backup and handover packages. Recent locations derive from committed records. There is no automatic phone/laptop sync.

## Phase 4.1 — Photo annotation

While editing a finding, choose **Annotate a copy** under a photo. Use arrows, rectangles, circles/ovals or text; adjust unsaved marks with Undo/Redo, selection and movement controls. **Save marked copy** adds a separate flattened PNG. Original photos and captions stay unchanged. To correct baked-in marks later, return to the unmarked source and create another copy.

In Reports, expand **Photographs included in this report** to choose originals, marked copies or both. Saved copies survive normal backups and reviewed phone/laptop event handover. Drawing operations are not autosaved: save the marked copy before leaving the editor. Copies are report-sized, up to1600px; no calibrated measurements or redaction are provided.

Start with the synthetic training example and wait for **Application available offline**. If an update is offered, save/close any editor before **Update & reload**. Appearance offers Light, Dark and System. Printed reports stay white.

Records stay in browser storage. Keep downloaded backups separately. Work on one device at a time and use reviewed event packages for handover; there is no live synchronisation. Actual Android annotation acceptance remains pending.
